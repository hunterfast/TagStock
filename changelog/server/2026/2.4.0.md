# Server 2.4.0

_Stand: 2026-10-15_

## Geändert
- **Der Server fragt bei GitHub nicht mehr von selbst.** Bisher sah er jede
  Minute nach, ob etwas veröffentlicht wurde, dazu beim Start, alle sechs
  Stunden nach der App und einmal am Tag nach dem eigenen Stand. Das ist alles
  weg.

  Jetzt fragt er nur noch, wenn **die App** (beim Öffnen von *Einstellungen*)
  oder die Weboberfläche wissen will, was bereitliegt – und auch dann
  **höchstens einmal pro Woche**. Dazwischen antwortet er aus dem Gedächtnis.
  Der Knopf *Nach Aktualisierungen sehen* fragt weiterhin sofort.

- **Eine Liste für alles.** App und Server teilen sich jetzt dieselbe Abfrage
  der Veröffentlichungen, statt jeweils eine eigene zu stellen. Ob eine neue
  App da ist, steht schon im Namen der Veröffentlichung (`app-v2.2.0+8`) – dafür
  muss nichts weiter abgerufen werden. Geladen wird nur, was wirklich neu ist.

- **Gemerkt über Neustarts hinweg** in `/data/app/veroeffentlichungen.json`.
  Ein Neustart – auch der nach dem Selbstaktualisieren – löst keine neue
  Abfrage aus.

- Hat sich seit der letzten Woche nichts getan, schickt GitHub nur
  „unverändert" zurück statt der ganzen Liste.

- Schlägt der Download einer App fehl, wird er nicht bei jeder Anfrage neu
  versucht, sondern erst wieder auf Knopfdruck oder nach der nächsten Woche.

- In der Weboberfläche steht unter *System*, wann zuletzt bei GitHub gefragt
  wurde.

## Belegt
An einem nachgebauten GitHub, das jede Anfrage zählt: Nach dem Start null
Anfragen. Die App fragt sechsmal und die Oberfläche einmal – eine Anfrage bei
GitHub. Der Knopf fragt sofort, bekommt aber nur „unverändert" zurück und lädt
nichts erneut. Nach einem Neustart und drei weiteren Anfragen der App: keine
einzige neue.

## Einstellungen
| Schalter | Standard | Wirkung |
|---|---|---|
| `TAGSTOCK_UPDATE_PRUEFEN` | `true` | `false`: nur noch auf Knopfdruck fragen |
| `TAGSTOCK_NACHSEHEN_TAGE` | `7` | Höchstens so oft wird gefragt |
| `TAGSTOCK_QUELLE` | leer | Woher die Liste kommt; die alten Namen `TAGSTOCK_APP_QUELLE` und `TAGSTOCK_SERVER_QUELLE` gelten weiter |

**Entfallen:** `TAGSTOCK_QUELLE_BEOBACHTEN`, `TAGSTOCK_QUELLE_TAKT_SEKUNDEN` und
`TAGSTOCK_UPDATE_QUELLE` – sie haben nichts mehr zu steuern. Sind sie gesetzt,
schadet das nicht.

## Bauläufe
Die Bau-Artefakte lagen 90 Tage bei GitHub und zählten gegen den Speicher des
Kontos (bei GitHub Free 500 MB) – zuletzt 1,39 GB. Das Server-Jar als Artefakt
entfällt (es liegt ohnehin in der Veröffentlichung), die APK bleibt nur noch zwei
Tage, die Testberichte vierzehn.
