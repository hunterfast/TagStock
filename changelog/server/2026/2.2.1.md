# Server 2.2.1

_Stand: 2026-09-11_

## Behoben
- **Der Server startete nach dem Update auf 2.2.0 nicht mehr.** Mit 2.2.0 kam
  ein Index auf der neuen Spalte `behaelter_kennung` dazu – und der stand in
  `schema.sql`. Die läuft aber beim Aufbau der Datenbankverbindung, also
  *bevor* die Schemapflege fehlende Spalten ergänzen kann. Auf einer
  bestehenden Datenbank gab es die Spalte in diesem Moment noch nicht, das
  `CREATE INDEX` scheiterte mit „no such column: behaelter_kennung", und der
  Server kam gar nicht erst hoch.

  Auf einer frischen Datenbank fiel das nicht auf, weil `CREATE TABLE` die
  Spalte gleich mitbringt – und genau so laufen alle Tests. Der Fehler traf
  deshalb ausschließlich beim Aktualisieren.

  Der Index wird jetzt von der Schemapflege angelegt, nachdem die Spalten
  stehen. **Daten waren zu keiner Zeit in Gefahr**: Der Server ist nur nicht
  gestartet, geschrieben hat er nichts.

## Damit das nicht wiederkommt
- Ein neuer Test (`AltbauTest`) fährt den Server gegen eine Datenbank hoch, die
  aus einer älteren Fassung stammt – ohne die Behälter-Spalten. Startet er
  nicht, schlägt der Test fehl. Alle anderen Tests legen eine frische Datenbank
  an und hätten diesen Fehler nie gefunden.
- In der Schemapflege steht jetzt ausdrücklich, dass ein Index auf einer neuen
  Spalte dorthin gehört und nicht nach `schema.sql`.

## Was zu tun ist
Einmal aktualisieren – am Host mit `sh server/update.sh`. Beim Start ergänzt
der Server die fehlenden Spalten und den Index selbst.
